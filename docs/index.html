当 APK 触发拒答：
利用模型护栏的主动防御

大模型正在降低逆向工程的门槛。我们提出 SRT（Safety-Refusal Trigger）， 一种利用模型安全护栏的主动防御机制——通过在 APK 中嵌入无害化的策略敏感内容， 在模型读取时触发安全拒答，干扰自动化逆向分析流程。

Background

LLM 辅助逆向：新的挑战

LLM 辅助的逆向分析工具能够自动读取反编译代码、调用分析工具、恢复业务逻辑。 这些能力在降低人工逆向成本的同时，也放大了应用代码保护的挑战。

🔓

知识产权暴露风险

代码语义恢复不再完全依赖人工分析，专有业务逻辑更容易被理解和还原

⚙️

自动化分析能力

Agent 可执行多步分析与工具调用，支持批量化逆向作业

🏴

滥用风险上升

自动化能力降低了漏洞挖掘和应用复制的技术门槛

⚠️ 传统保护的局限

加壳/加固：主要提高静态分析和脱壳成本，但 Agent 可识别常见加固模式
代码混淆：降低代码可读性，但 LLM 在理解混淆代码方面展现出较强能力
反调试：干扰动态分析，但 Agent 可通过工具调用尝试绕过检测

Approach

SRT：基于安全护栏的防御机制

我们探索了一种不同于传统代码保护的思路：不增加代码复杂度，而是利用模型自身的安全对齐机制。 通过在 APK 中嵌入经过无害化处理的策略敏感语义，当这些内容在逆向分析过程中被模型读取时， 可能触发模型的安全护栏，导致分析流程中断。

🧪

无害化处理

从公开来源收集 CBRN 相关语料，剥离可执行的操作细节，仅保留可能触发护栏的高层语义特征——既保留触发能力，又消除实际危害。

💉

嵌入 APK 工件

将 SRT 嵌入 AndroidManifest.xml 或关键代码位置。当 Agent 读取全局信息或分析目标逻辑时，SRT 内容随工件一起进入模型上下文。

🛡️

护栏响应

策略敏感语义可能激活模型的安全对齐机制，产生 "Chat paused"、"对话断开" 等拒答响应，导致自动化逆向分析流程中断。

🔄

保持应用功能

SRT 是非可执行的元数据或注释文本，不影响 APK 运行时行为，仅在被 LLM Agent 作为上下文读取时发挥作用。

💡 核心思路

传统防护主要作用于代码与分析工具的接口，而 LLM 辅助逆向引入了新的接口——「应用工件 → 模型上下文」。 这条通道为防御提供了新的切入点。SRT 尝试在这个接口层面干预模型的分析行为，利用模型自身的安全机制为应用保护服务。

Experimental Setup

实验材料与配置

我们在 6 款真实开源 Android 应用上进行测试，使用 4 类 CBRN 语义和 3 套 LLM Agent 配置， 完成主实验 72 次分析运行和消融实验 24 次文本对照测试。

📱 6 款 Android 应用

  • Notes（笔记）
  • Paint（绘图）
  • Musicplayer（音乐）
  • Clock（时钟）
  • Filemanager（文件）
  • Voicerecorder（录音）

🧪 4 类 SRT 语义

  • C - 化学（Chemical）
  • B - 生物（Biological）
  • R - 放射性（Radiological）
  • N - 核（Nuclear）

🤖 3 套 Agent 配置

  • Claude Code + Sonnet 5
  • Codex + GPT-5.6 Terra
  • Codex + Grok 4.5

Key Findings

核心发现

初步结果表明：在评估的非自适应场景下，SRT 能够以较高概率触发模型护栏。 我们观察到模型配置、语义类别、注入位置等因素对触发效果的显著影响。

发现 2

模型配置显著影响触发效果

差异达 46 个百分点，反映了不同模型的护栏策略和安全对齐强度的显著不同。 Claude Opus 5 配置的触发率最高（79.2%），Grok 4.5 配置最低（33.3%）。

发现 3

不同 CBRN 类别的触发差异

扩展到全部 6 个 APK 后，触发率呈现 C（83.3%）> B（75.0%）> R（58.3%）> N（41.7%） 的单调排序。

Task 1 观察：B 类最容易触发强阻断且未出现安全替代，而从 C、R 到 N 类， 强阻断数量总体下降、安全替代数量总体增加，说明模型会根据不同 CBRN 类别采用不同强度和形式的安全响应。

发现 4

嵌入位置影响触发概率

Global（Manifest）的总体触发率比 Local（代码）高 20.8 个百分点（75.0% vs 54.2%）。 Manifest 作为 Agent 早期检索的目标，在当前评估场景下触发率相对较高，但也更容易被识别。

发现 5

重复测试的稳定性（Pass@3）

四个 APP、四种模型组合共完成 48 次运行。Claude + 定向 Prompt 的总体触发率最高，为 75.0%； GPT + 泛化 Prompt 最低，为 41.7%。

说明模型及提示词选择的组合会显著影响重复触发表现。定向功能描述可能提高模型对注入关联位置的关注度， 从而增加触发概率。

发现 6

无害化处理保留触发能力

消融实验（2 APK × 4 SRT × 3 Agent）对比了三种文本条件：无害化 SRT 保留了 91.7% 的触发能力（11/24 vs 未净化 12/24）， 而长度匹配的随机文本触发率为 0（0/24）。

① 观测到的触发行为与策略敏感语义相关，而非文本注入行为本身
② 触发特征与可执行细节可以在一定程度上解耦——SRT 在保留触发能力的同时，移除了实际操作步骤，降低了双重用途风险
Discussion

关键观察与局限

作为探索性研究，我们观察到了一些值得关注的现象

🎯 模型配置依赖性

触发效果与模型配置强相关。评估的三个配置中，Claude Opus 5 配置触发率最高（79.2%），Grok 4.5 配置最低（33.3%）， 差距达 46 个百分点。

📍 嵌入位置影响

Global SRT（AndroidManifest.xml）的平均触发率为 75%，Local SRT（关键代码位置）为 54.2%。 应用间异质性较强，说明注入位置效应可能受业务结构、文件布局或 Agent 检索路径共同影响。

🔄 语义恢复能力

即使将策略敏感语义拆分并嵌入无害文本中，评估的四个模型仍全部拦截。 这表明护栏机制不仅依赖连续关键词匹配，而是具备一定的跨上下文语义恢复能力。

📏 重要局限

评估范围：本研究针对非自适应的首轮分析场景。我们尚未评估 SRT 对自适应分析者（预先过滤、分段提交、切换模型等策略）的鲁棒性。
可移除性：当前评估的 Manifest 载体位置明显，一旦被识别可被移除。更隐蔽和分散的嵌入方式是未来研究方向。
模型护栏依赖：触发效果依赖模型的护栏策略。不同模型、不同账号、不同客户端的护栏强度可能存在差异。模型更新也可能改变护栏行为。
样本规模：主实验使用了固定的四个 SRT 实例（每类一个），在六个应用上进行评估。一些因素效应基于有限样本，需要更大规模验证。

🚀 后续研究方向

更隐蔽的嵌入：探索语义级、分散式的嵌入结构，提高识别和移除的难度
自适应场景评估：评估对具备预处理和过滤能力的自适应分析者的有效性
组合防御策略：研究 SRT 与传统保护方法（混淆、加固）的组合应用
扩展评估：扩大 SRT 实例数量、应用范围和模型覆盖，建立系统化的评测基准
